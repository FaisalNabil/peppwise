What I Build

One service. Three country models.

Every e-invoicing mandate fits one of three architectures. I have built production integrations in each — so wherever your next market is, the model is already familiar.

peppol_c4.cfg – ▢ ✕
Peppol · 4-Corner

C4 — Network Exchange

The classic Peppol model: invoices flow between trading partners through certified Access Points. No tax authority in the loop.

  • Access Point & SMP/SML setup
  • BIS 3.0 / PINT document mapping
  • AS4 messaging, MLR handling
  • EU · Australia/NZ · Japan markets
How C4 Works
peppol_c5.cfg – ▢ ✕
Peppol · 5-Corner

C5 — Tax Authority CTC

Peppol exchange plus a fifth corner: the tax authority receives invoice data continuously. The model regulators are converging on.

  • Singapore — IRAS C5 GST transmission
  • UAE — FTA via DCTCE, Tax Data Document
  • PINT SG / PINT AE specialisations
  • ASP / Access Point integration

direct_clearance.cfg – ▢ ✕
Non-Peppol · National API

Direct Clearance

No Peppol network — invoices clear directly through the tax authority's own API before they are valid. Each country builds its own.

  • Malaysia — IRBM MyInvois API
  • UBL 2.1, X.509 signature, all 5 doc types
  • 72-hour rejection & cancellation flow
  • PINT MY alignment on the horizon
